# 스캔 히스토리

스캔 히스토리 페이지는 프로젝트에 제출된 모든 스캔을 역순으로 나열합니다.

URL: `/projects/{id}/scan-history`

---

## 표시 내용

| 컬럼 | 설명 |
|---|---|
| **상태** | PENDING / SCANNING / ANALYZING / COMPLETED / FAILED |
| **버전** | 스캔 시점의 프로젝트 버전 문자열. FAILED 행은 버전 아래에 요약된 오류 메시지도 표시 |
| **스캔 일시** | 스캔 제출 타임스탬프 (`yyyy-MM-dd HH:mm`) |
| **소스** | 버전을 가져온 경로 — **Git** (GitHub 연동) 또는 **CLI** (CLI 스캔 도구); 가져오기 기록이 없으면 `-` |
| **컴포넌트** | 감지된 총 컴포넌트 수 |

페이지 헤더에는 전체 스캔 수도 표시됩니다.

---

## 스캔 상태

| 상태 | 설명 |
|---|---|
| `PENDING` | 스캔 수신됨; 처리 대기 중 |
| `SCANNING` | 의존성 매니페스트 파싱 중 |
| `ANALYZING` | CVE 및 라이선스 보강 진행 중 (OSV / deps.dev) |
| `COMPLETED` | 모든 보강 완료; 보안 센터 최신 상태 |
| `FAILED` | 오류 발생; 스캔 행의 오류 메시지 확인 |

---

## 오프라인 모드: 정의 기준일

서버가 오프라인(air-gapped) 모드(`oswl.airgapped.enabled=true`)로 실행 중이면 페이지 상단에 다음 배너가 표시됩니다.

> 오프라인 모드 — {date} 기준 취약점 정의로 분석된 결과입니다.

날짜는 가져온 오프라인 스냅숏 소스 중 가장 오래된 정의 기준일이며, 감사자가 분석 시점의 취약점 데이터가 얼마나 최신이었는지 확인할 수 있게 합니다. air-gapped 모드가 아니거나 스냅숏 출처가 없으면 배너는 숨겨집니다.

---

## 스캔 삭제

상단 바의 버전 드롭다운에서 삭제합니다: 버전 항목에 마우스를 올리면 나타나는 **삭제**(휴지통) 아이콘을 클릭한 뒤 확인합니다. 이 작업에는 `SCAN_HISTORY_DELETE` 권한(또는 `SYSTEM_ADMIN` 역할)이 필요하며, 해당 스캔 레코드와 모든 컴포넌트 데이터를 영구적으로 제거합니다. 삭제 내역은 감사 로그에 기록됩니다.

> ⚠️ 이 작업은 되돌릴 수 없습니다. 스캔을 삭제하면 리스크 트렌드 차트에서도 제거됩니다.

---

## 스캔 재제출

OsWL은 **동일한 버전** 문자열에 대한 스캔 재제출을 지원합니다. 서버가 기존 스캔 레코드를 초기화하고 새 페이로드를 재처리합니다. 이전 스캔이 보강 중간에 실패했거나, 버전 변경 없이 의존성이 변경된 경우에 유용합니다.

재스캔 방법: CLI를 통해 동일한 버전 제출 (`POST /api/scan`) — OsWL이 버전 일치를 감지하고 자동으로 레코드를 초기화합니다.
