# 사용자 가이드

이 페이지는 OsWL 웹 대시보드의 일상적인 사용법을 설명합니다.

**시스템 관리자**가 아니면 **멤버로 등록된 프로젝트**만 보입니다. 프로젝트 안에서 할 수 있는 일은 **역할 템플릿**(Admin / Developer / Viewer)에 따릅니다. [권한 레이어](Authorization-Layers.md) 참고.

---

## 프로젝트 대시보드 (`/projects`)

프로젝트 대시보드는 로그인 후 첫 화면입니다. 모든 활성 프로젝트를 카드 형식으로 보여줍니다.

### 프로젝트 카드

각 카드에 표시되는 정보:

| 필드 | 설명 |
|---|---|
| **이름** | 프로젝트 표시 이름 |
| **버전** | 최신 스캔의 버전 문자열 |
| **VCS 배지** | VCS에서 임포트된 경우 GitHub / GitLab / Bitbucket 아이콘 |
| **브랜치** | 가장 최근에 임포트된 브랜치 |
| **마지막 스캔** | 가장 최근 완료된 스캔의 상대적 타임스탬프 |
| **리스크 배지** | CRITICAL / HIGH / MEDIUM / LOW CVE 수 |
| **라이선스 배지** | 가장 심각한 라이선스 상태 (Restricted / Caution / Permitted / Unknown) |

### 프로젝트 액션

프로젝트 카드를 클릭하면 **보안 센터**가 열립니다.  
카드의 더보기 메뉴(⋮)에서 다음 작업을 수행할 수 있습니다:

* **상세 보기** — 보안 센터
* **라이선스 분석** — 라이선스 리스크 페이지
* **리스크 트렌드** — 히스토리 차트
* **스캔 히스토리** — 모든 스캔 목록
* **휴지통으로 이동** — 프로젝트 소프트 삭제

---

## 프로젝트 생성

프로젝트를 등록하는 두 가지 방법:

1. **Quick Import** — VCS 계정을 연결하고 저장소/브랜치를 선택합니다. [Quick Import](Quick-Import.md) 참조.
2. **CLI 푸시** — API 키로 프로젝트를 생성한 후 빌드 파이프라인에서 스캔 페이로드를 제출합니다. [CLI 연동](CLI-Integration.md) 참조.

### Quick Import 진행 상황

Quick Import를 실행하면 진행 카드에 연속적인 퍼센트와 예상 남은 시간이 표시됩니다. 컴포넌트 보강 중에는 컴포넌트별 CVE 건수 같은 상세 줄이 나타날 수 있습니다. deps.dev 캐시 적중이 있으면 "1,204개 중 1,180개는 캐시에서 즉시 처리"와 같은 배지가 표시되며, 캐시가 없는 최초 스캔에서는 배지가 숨겨집니다. CVE/라이선스 데이터 파이프라인이 끝나면 작업이 **완료** 상태로 전환되며, 이때 AI 요약은 여전히 백그라운드에서 생성될 수 있습니다.

## 휴지통

삭제된 프로젝트는 **휴지통** 섹션(프로젝트 목록 하단)에 표시됩니다.

| 작업 | 설명 |
|---|---|
| **복원** | 프로젝트를 활성 상태로 되돌림 |
| **영구 삭제** | 모든 데이터(스캔, CVE 등) 복구 불가 삭제 |
| **선택 복원** | 여러 프로젝트 일괄 복원 |
| **휴지통 비우기** | 휴지통의 모든 프로젝트 영구 삭제 |

---

## 프로젝트 내 탐색

프로젝트 내에서 사이드바를 통해 다음 섹션에 접근할 수 있습니다:

| 섹션 | URL 패턴 | 설명 |
|---|---|---|
| 보안 센터 | `/projects/{id}/security-center` | CVE 목록 및 상태 관리 |
| 라이선스 분석 | `/projects/{id}/license` | 의존성 라이선스 컴플라이언스 |
| 리스크 트렌드 | `/projects/{id}/risk-trend` | 히스토리 리스크 차트 |
| 버전 비교 | `/projects/{id}/version-diff` | 두 스캔 비교 |
| 스캔 히스토리 | `/projects/{id}/scan-history` | 모든 과거 스캔 |
| CLI / API 키 | 설정 → CLI 탭 | 프로젝트 API 키 관리 |

## AI 요약

AI가 활성화되면 OsWL은 스캔 데이터가 준비된 뒤 보안 자세(posture), 트렌드, 라이선스 위험 요약을 생성합니다. 따라서 AI 요약이 끝나기 전에도 스캔이 완료되고 보안 센터를 즉시 사용할 수 있습니다. AI가 실행 중일 때 보안 센터 상단에 "AI 요약 생성 중…" 스켈레톤이 표시되며, 완료되면 페이지를 새로고침하지 않고 인사이트가 채워집니다. AI가 설정되지 않은 경우 스켈레톤은 표시되지 않고 스캔 결과에는 영향이 없습니다.

OsWL은 입력 컨텍스트 해시로 AI 요약을 캐싱하므로, 재스캔 시 변경되지 않은 컴포넌트는 AI 호출을 다시 하지 않습니다. 개별 컴포넌트 상세 패널에서는 여전히 수동으로 요약을 재생성할 수 있습니다.

## 오프라인(에어갭) 모드

관리자는 `oswl.airgapped.enabled=true`로 에어갭 모드를 켤 수 있습니다. 이 모드에서는 취약점/위협 인텔리전스 조회(OSV, deps.dev, EPSS, CISA KEV)를 실시간 외부 API가 아닌 가져온 오프라인 스냅샷 저장소에서 제공하며, 외부 HTTP 호출을 시도하지 않습니다.

**Administration → Offline Snapshot** 탭에서 번들 가져오기·내보내기, 소스별 레코드 수와 정의 최신성을 확인할 수 있습니다. 최신성 배지는 가져온 시각이 아니라 상류 데이터의 기준일 중 가장 오래된 값을 기준으로 계산됩니다. 오프라인 정의로 분석된 스캔 결과와 export에는 "YYYY-MM-DD 기준 취약점 정의로 분석된 결과입니다"라는 안내가 포함됩니다. 설정 방법은 [Administration](Administration.md)을 참조하세요.

## 내장 AI 모델

OsWL의 내장 로컬 AI는 llama.cpp 사이드카를 실행하며, 기본 모델로 **Qwen3 1.7B** GGUF를 사용합니다. 최초 부팅 시 `oswl.ai.embedded.auto-download-on-boot` 설정이 켜져 있고 에어갭 모드가 아니라면 기본 모델을 백그라운드에서 미리 다운로드해, Settings에서 시작을 누를 때 대기 시간을 줄입니다. 기본 다운로드는 OsWL 자체 GitHub Release 자산을 사용하며 실패하면 원본 Hugging Face 저장소로 폴백합니다. 모든 다운로드는 SHA-256 체크섬으로 검증됩니다. 설정된 embedded-ai 디렉터리에 호환되는 임의의 `.gguf` 파일을 직접 넣을 수도 있습니다. 설치 및 문제 해결은 [Embedded AI](Embedded-AI.md)를 참조하세요.

## 컴포넌트 상세

보안 센터 또는 라이선스 뷰에서 컴포넌트(라이브러리)를 클릭하면 **컴포넌트 상세** 패널이 열립니다.

표시 내용:

* 전체 이름, 버전, 에코시스템
* deps.dev의 업스트림 프로젝트 레코드에서 가져온 **프로젝트 설명**, 홈페이지, 소스 저장소 링크 — OpenSSF Scorecard를 조회할 때 이미 호출하는 API를 그대로 사용하므로 추가 비용 없이 보강 과정에서 채워집니다
* CVSS 점수, 설명, 수정 버전이 포함된 CVE 목록 — 위쪽의 라이선스/버전 배지와 시각적으로 구분된 **보안 취약점(Security Issues)** 영역에 그룹화되어 표시됩니다
* 라이선스 이름 및 컴플라이언스 상태
* AI 생성 라이선스 리스크 요약 (AI가 설정된 경우)
* 패치 가능 여부 (Patchable / Non-Patchable / Unknown)
* 최신 버전 및 지원 중단 공지 (deps.dev 기반)
* 의존성 경로 (직접 의존성 vs. 전이적 의존성)

업스트림에 공개된 설명이 없는 패키지는 그 사실을 명시하고, 아무것도 표시하지 않는 대신 소스 저장소 링크를 안내합니다.
