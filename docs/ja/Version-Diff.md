# バージョン比較

バージョン比較ページでは、2 つのスキャン結果を並べて比較し、バージョン間でどのコンポーネントが追加・削除・変更されたかを確認できます。

URL: `/projects/{id}/version-diff`

---

## 使い方

1. プロジェクトを開き、サイドバーの**バージョン比較**に移動します。
2. 左のドロップダウンから**ベース**スキャン（古いバージョン）を選択します。
3. 右のドロップダウンから**比較対象**スキャン（新しいバージョン）を選択します。
4. **比較**をクリックします。

OsWL は差分を計算し、次の 3 つのセクションで表示します:

---

## 差分セクション

### 追加されたコンポーネント

**比較対象**スキャンには存在するが、ベーススキャンには**存在しない**コンポーネントです。

これは 2 つのバージョンの間に新たに導入された依存関係です。CRITICAL や HIGH の CVE を持つものには特に注意してください — 新たな攻撃対象領域となります。

### 削除されたコンポーネント

**ベース**スキャンには存在するが、比較対象スキャンには**存在しない**コンポーネントです。

これらの依存関係は取り除かれました。既知の CVE を持つものが含まれていた場合、その削除は良い兆候です。

### 変更されたコンポーネント

**両方の**スキャンに存在するが、**バージョンが異なる**コンポーネントです。

| カラム | 説明 |
|---|---|
| **コンポーネント** | ライブラリ名 |
| **ベースバージョン** | ベーススキャンでのバージョン |
| **比較バージョン** | 比較対象スキャンでのバージョン |
| **CVE 差分** | CVE 件数の変化（例: −2 CRITICAL は 2 件の Critical CVE が解消されたことを意味） |

CVE を解消したアップグレードは負の CVE 差分（緑）で表示されます。新たな CVE を持ち込むダウングレードやバージョン変更は正の差分（赤）で表示されます。

> あるライブラリが**同一スキャン内で複数バージョン**として現れる場合（ダイヤモンド依存関係 — 例: 2 つの推移的パスが同じパッケージの異なるメジャーバージョンを引き込んでいる場合）、各バージョンは 1 行にまとめられるのではなく、それぞれ個別に追跡・比較されます。

---

## ユースケース

* **リリース前レビュー**: リリース候補を前回のリリースと比較し、新たな高深刻度 CVE が持ち込まれていないか確認する。
* **依存関係監査**: 2 つのフィーチャーブランチを比較し、PR における依存関係変更のリスク影響を把握する。
* **修正の検証**: 特定のライブラリをアップグレードすることで、期待した CVE が実際に解消されたか確認する。
* **リグレッション検出**: 依存関係解決の競合によって偶然発生したバージョンのダウングレードを特定する。

---

## ヒント

* 差分は保存済みのスキャンデータから即座に計算されます — 再スキャンは不要です。
* 両方のスキャンでコンポーネント一覧が同一でバージョン変更がない場合、3 つのセクションはすべて空になります（バージョンが同一）。
* 比較したいスキャン ID を見つけるには[スキャン履歴](Scan-History.md)を使用してください。
