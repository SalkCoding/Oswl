# セキュリティセンター

セキュリティセンターは OsWL における主要な脆弱性管理インターフェースです。プロジェクトの最新スキャンで検出されたコンポーネントに影響するすべての CVE を、フィルタリング・ソート可能な一覧として提供します。

URL: `/projects/{id}/security-center`

**アクセス:** `SECURITY_CENTER_VIEW`（またはシステム管理者）**および** [プロジェクトメンバーシップ](Authorization-Layers.md)が必要です。エクスポートと印刷には `SECURITY_CENTER_EXPORT`、状態変更には `SECURITY_CENTER_UPDATE_STATUS` が必要です。

---

## CVE 一覧の見方

セキュリティセンターの各行は、スキャンされたコンポーネントに紐づく 1 件の **CVE**（Common Vulnerabilities and Exposures）エントリを表します。

| カラム | 説明 |
|---|---|
| **コンポーネント** | ライブラリ名とバージョン |
| **エコシステム** | パッケージエコシステム（MAVEN、NPM、PYPI など） |
| **CVE ID** | deps.dev/OSV による CVE または GHSA 識別子（例: `CVE-2021-44228`） |
| **CVSS スコア** | 数値の深刻度スコア（0.0〜10.0） |
| **深刻度** | CRITICAL / HIGH / MEDIUM / LOW |
| **修正バージョン** | 推奨される修正バージョン（判明している場合） |
| **状態** | 現在のトリアージ状態 |
| **パッチ適用可否** | 修正が利用可能かどうか |

---

## 深刻度レベル

OsWL は標準的な CVSS 3.x の範囲を使って CVSS ベーススコアを深刻度区分にマッピングします。

| 深刻度 | CVSS スコア範囲 | 意味 |
|---|---|---|
| **CRITICAL** | 9.0〜10.0 | リモートから悪用可能で影響大 — 直ちに修正 |
| **HIGH** | 7.0〜8.9 | 深刻なリスク — 今スプリントで優先対応 |
| **MEDIUM** | 4.0〜6.9 | 中程度のリスク — 近いうちに修正 |
| **LOW** | 0.1〜3.9 | 軽微なリスク — 都合の良いタイミングで修正 |
| **NONE** | 0.0 | 情報提供のみ／有効なスコアなし |

## CVE ステータスのライフサイクル

プロジェクト内の各 CVE には、次のいずれかのステータスを割り当てられます。

| ステータス | 意味 |
|---|---|
| **OPEN** | 新規検出 — レビューが必要 |
| **IN_PROGRESS** | 対応中 |
| **SUPPRESSED** | リスクを認識済み。この文脈では当面の優先対応ではない |
| **FALSE_POSITIVE** | 該当しないことを確認済み（例: 脆弱なコードパスに到達しない） |
| **RESOLVED** | 修正済み — アップグレード適用またはコンポーネント削除 |

> ステータス更新に必要な権限: `SECURITY_CENTER_UPDATE_STATUS` またはシステム管理者。

---

## フィルタリングとソート

セキュリティセンター上部のフィルターバーで一覧を絞り込めます:

* **深刻度** — CRITICAL / HIGH / MEDIUM / LOW
* **状態** — OPEN / IN_PROGRESS / SUPPRESSED / FALSE_POSITIVE / RESOLVED
* **エコシステム** — MAVEN / NPM / PYPI など
* **パッチ適用可否** — Patchable / Non-Patchable / Unknown
* **検索** — CVE ID とコンポーネント名にまたがるフリーテキスト検索

任意のカラムヘッダーをクリックすると昇順／降順でソートできます。専用の**並び替え**セレクターは基本の並び順を制御します: **リスク（既定）**（深刻度の高い順）、**名前**、または**ライセンスリスク**。

---

## 一括ステータス更新

1. チェックボックスで 1 件以上の CVE を選択します。
2. アクションツールバーの**ステータス更新**をクリックします。
3. ドロップダウンから新しいステータスを選択します。
4. 確定します。

選択したすべての CVE が単一のトランザクションで更新されます。

---

## エクスポート（v1.0.4）

アクションツールバーの**エクスポート**ドロップダウンは、最新の完了スキャンから標準準拠の成果物を生成します:

| 項目 | エンドポイント | 形式 |
|---|---|---|
| SBOM（CycloneDX） | `GET /api/projects/{projectId}/sbom` | CycloneDX 1.6 JSON |
| VEX | `GET /api/projects/{projectId}/vex` | CycloneDX VEX — トリアージ判断を反映 |
| SARIF | `GET /api/projects/{projectId}/sarif` | SARIF 2.1.0、GitHub コードスキャンにアップロード可能 |
| コンプライアンスレポート | `GET /security-center/compliance-report` | 印刷用 HTML（*印刷 → PDF として保存*を使用） |
| CVE／ライセンス CSV | — | 現在フィルタリングされているビュー |

一括操作には**アップグレード PR を作成**も含まれます。選択したすべてのコンポーネントを修正バージョンに引き上げる単一のプルリクエストを作成します。

詳細は[v1.0.4 の新機能](Whats-New-v1.0.4.md)を参照してください。

## コンポーネント詳細

コンポーネント名をクリックすると**コンポーネント詳細**サイドパネルが開き、次が表示されます:

* deps.dev のプロジェクトレコードから取得した、そのライブラリが実際に何であるかの簡単な説明、およびホームページ／ソースリポジトリへのリンク
* そのライブラリのすべての CVE（CVSS の詳細分析を含む）— 上部のバッジとは区別された**セキュリティ課題（Security Issues）**見出しの下にグループ化
* ライセンス名とコンプライアンス状態
* AI 生成のライセンスリスク要約
* 最新の利用可能バージョンと非推奨通知
* 完全な依存関係パス（直接 vs. 推移的）
* サプライチェーンヒューリスティックがパッケージを検出した場合の **OpenSSF Scorecard** スコア、**既知の悪性** / **タイポスクワッティングリスク**バッジ（v1.0.4）
* Jira 連携が設定されている場合の**Jira 課題を作成**ボタン（v1.0.4）。作成後はバッジが直接 Jira の課題にリンクし、作成に失敗した場合はアプリの他の箇所と同じスタイルのトーストで理由が表示されます

長い CVE の説明は折りたたまれた行では省略されますが、行をクリックすると展開されアドバイザリの全文が表示されるため、*なぜ*それが脆弱性なのかを常に確認できます。

パネルには対応アクションもあります: **パッチを適用（PR を作成）**と**保留**です。保留には理由と有効期限プリセット（1 週間 / 1 / 3 / 6 か月、カスタム日付、または無期限）を記録します。カスタム有効期限は**未来の日付**でなければなりません — 過去の日付や不正な形式は HTTP 400 で拒否され、日付ピッカーでも明日以降しか選択できません。

PR/MR が作成されると、成功パネルに目立つ**PR/MR を見る**ボタンと、折りたたみ可能な**「変更内容は？」**要約（パッチ済みのマニフェストファイルパスとバージョンの引き上げ、例: `pom.xml`: `log4j-core 2.14.1 → 2.17.0`）が表示されます。

コンポーネントの保留期間が切れると（夜間スケジューラーにより）、保留は解除され、セキュリティセンターには保留が過去 7 日以内に終了したコンポーネントに対して閉じることのできる**🦉フクロウのリマインダーバナー**が表示され、再レビューを促します。

## AI セキュリティインサイト

AI プロバイダーが設定されている場合（**設定 → AI**）、各完了スキャンごとにセキュリティセンター上部に 1 段落の AI 要約が生成されます:

* **セキュリティポスチャーインサイト** — 現在の CVE 件数と深刻度分布の総合評価
* **セキュリティリスクトレンドインサイト** — 前回スキャンとの比較による改善・悪化の傾向

AI インサイトはスキャンごとに 1 回生成され、新しいスキャンが送信されない限り再生成されません。

---

## パッチ適用可否

OsWL はライブラリのすべての CVE にまたがる `fixVersion` フィールドからパッチ適用可否を導出します:

| 状態 | 条件 |
|---|---|
| **PATCHABLE** | 少なくとも 1 件の CVE に既知の修正バージョンがある |
| **NON_PATCHABLE** | CVE は存在するが、既知の修正がない |
| **UNKNOWN** | CVE がない、または CVE データがまだエンリッチされていない |

---

## データソース

CVE データは 2 つのソースから取得され統合されます:

* **deps.dev** — `GetAdvisory` による GHSA アドバイザリ、CVE エイリアス、CVSS スコア、タイトル
* **OSV**（Open Source Vulnerabilities） — `POST https://api.osv.dev/v1/querybatch` による概要、修正バージョン、**CWE ID**（`database_specific.cwe_ids`）

OSV が提供する場合、CWE 識別子（例: `CWE-79`）はコンポーネント詳細パネルに表示されます。

v1.0.4 以降、優先順位付けのための 2 つのフィードも統合されています:

* **CISA KEV** — *Known Exploited Vulnerabilities* カタログ。KEV への収載は実際に悪用が確認されていることを意味し、トリアージ順では生の CVSS スコアより優先されます。
* **EPSS**（FIRST.org） — 今後 30 日間の悪用確率で、KEV に載っていないすべての項目の優先順位付けに使われます。

テスト・開発専用の依存関係はその scope でタグ付けされ、一覧から隠して本番リスクを際立たせることができます。除外ではなくタグ付けなので、SBOM から何かが消えることはありません。

エンリッチメントは各スキャン後に自動実行され、**設定 → キャッシュ**（`/api/settings/cache`）のキャッシュポリシーに従って更新されます。
