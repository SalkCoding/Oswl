# ユーザーガイド

このページでは OsWL Web ダッシュボードの日常的な使い方を説明します。

表示されるのは自分が**メンバー**であるプロジェクトのみです（**システム管理者**を除く）。プロジェクト内でできることは **ロールテンプレート**（Admin / Developer / Viewer）によって決まります。[権限レイヤー](Authorization-Layers.md)を参照してください。

---

## プロジェクトダッシュボード（`/projects`）

プロジェクトダッシュボードはログイン後の最初の画面です。すべてのアクティブなプロジェクトがカード形式で表示されます。

### プロジェクトカード

各カードには次の情報が表示されます:

| 項目 | 説明 |
|---|---|
| **名前** | プロジェクトの表示名 |
| **バージョン** | 最新スキャンのバージョン文字列 |
| **VCS バッジ** | VCS からインポートされた場合、GitHub / GitLab / Bitbucket のアイコン |
| **ブランチ** | 最後にインポートされたブランチ |
| **最終スキャン** | 直近の完了スキャンからの相対時刻 |
| **リスクバッジ** | CRITICAL / HIGH / MEDIUM / LOW の CVE 件数 |
| **ライセンスバッジ** | 最も悪いライセンス状態（Restricted / Caution / Permitted / Unknown） |

### プロジェクト操作

プロジェクトカードをクリックすると**セキュリティセンター**が開きます。
カードのケバブメニュー（⋮）から次の操作ができます:

* **詳細を見る** — セキュリティセンター
* **ライセンス分析** — ライセンスリスクページ
* **リスクトレンド** — 過去の推移グラフ
* **スキャン履歴** — すべてのスキャンの一覧
* **ゴミ箱へ移動** — プロジェクトのソフトデリート

---

## プロジェクトの作成

プロジェクトを登録する方法は 2 つあります:

1. **Quick Import** — VCS アカウントを接続し、リポジトリ／ブランチを選択します。[Quick Import](Quick-Import.md)を参照してください。
2. **CLI プッシュ** — API キーでプロジェクトを作成し、ビルドパイプラインからスキャンペイロードを送信します。[CLI 連携](CLI-Integration.md)を参照してください。

### Quick Import の進行状況

Quick Import の実行中は、進行状況カードに連続的なパーセンテージと推定残り時間が表示されます。エンリッチメント中は、コンポーネントごとの CVE 件数などの詳細行が表示されることがあります。実際に deps.dev のキャッシュヒットが発生すると、「合計 1,204 件のコンポーネント — うち 1,180 件はキャッシュから即時処理」のようなバッジが表示されます。まだ何もキャッシュされていない最初のスキャンでは、このバッジは表示されません。CVE とライセンスのデータパイプラインが完了すると、ジョブは直ちに**完了**状態になります — AI 要約はバックグラウンドで生成が続いている場合があります。

## ゴミ箱

削除されたプロジェクトは**ゴミ箱**セクション（プロジェクト一覧の下部）に入ります。

| 操作 | 説明 |
|---|---|
| **復元** | プロジェクトをアクティブな状態に戻す |
| **完全削除** | すべてのデータ（スキャン、CVE など）を復元不能な形で削除 |
| **選択項目を復元** | 複数プロジェクトの一括復元 |
| **ゴミ箱を空にする** | ゴミ箱内のすべてのプロジェクトを完全削除 |

## プロジェクト内の移動

プロジェクトに入ると、サイドバーから次の画面にアクセスできます:

| セクション | URL パターン | 説明 |
|---|---|---|
| セキュリティセンター | `/projects/{id}/security-center` | CVE 一覧とステータス管理 |
| ライセンス分析 | `/projects/{id}/license` | 依存関係のライセンスコンプライアンス |
| リスクトレンド | `/projects/{id}/risk-trend` | 過去のリスク推移グラフ |
| バージョン比較 | `/projects/{id}/version-diff` | 2 回のスキャンを比較 |
| スキャン履歴 | `/projects/{id}/scan-history` | 過去のすべてのスキャン |
| CLI / API キー | 設定 → CLI タブ | プロジェクト API キーの管理 |

## AI 要約

AI が有効な場合、OsWL はスキャンデータの準備が整った**あと**にセキュリティ状況（posture）、トレンド、ライセンスリスクの要約を生成します。そのため、AI 要約が完了する前にスキャンが完了し、セキュリティセンターを利用できるようになります。AI が実行中の間、セキュリティセンターには「AI 要約を生成中…」というスケルトン表示が現れ、準備が整うとページを再読み込みせずに最終的なインサイトが表示されます。AI が設定されていない場合、スケルトンは表示されず、スキャン結果にも影響はありません。

OsWL は入力のコンテキストハッシュを使って AI 要約をキャッシュするため、再スキャンで変更がなかったコンポーネントについては新たに AI を呼び出しません。個々のコンポーネントの要約は、コンポーネント詳細パネルから手動で再生成することもできます。

## オフライン（エアギャップ）モード

管理者は OsWL を閉域網（エアギャップ）モード（`oswl.airgapped.enabled=true`）で実行できます。このモードでは、脆弱性・脅威インテリジェンスの照会（OSV、deps.dev、EPSS、CISA KEV）は、外部のライブ API ではなくインポート済みのオフラインスナップショットから提供され、外部への HTTP 通信は一切行われません。

**Administration → Offline Snapshot** から、バンドルのインポート、現在のストアのエクスポート、ソースごとのレコード数と鮮度の確認ができます。鮮度バッジは、インポート時刻ではなく、インポートされた各ソースの上流「基準日」のうち最も古いものを基準としています。オフライン定義で分析されたスキャンおよびエクスポートには、「YYYY-MM-DD 時点の脆弱性定義で分析された結果です」という注記が付きます。設定方法は [Administration](Administration.md) を参照してください。

## 内蔵 AI モデル

OsWL の内蔵ローカル AI は llama.cpp サイドカーを実行し、既定モデルとして **Qwen3 1.7B** GGUF を使用します。初回起動時、OsWL は既定モデルをバックグラウンドで先読みダウンロードするため（`oswl.ai.embedded.auto-download-on-boot` で設定変更可能、閉域網（エアギャップ）モードでは無効）、設定画面で内蔵 AI を有効化する際の待ち時間が短縮されます。既定のダウンロードは OsWL 自身の GitHub Release アセットを使用し、失敗した場合は元の Hugging Face リポジトリへフォールバックします。すべてのダウンロードは SHA-256 チェックサムで検証されます。設定した embedded-ai ディレクトリに、互換性のある任意の `.gguf` ファイルを直接配置することもできます。インストールとトラブルシューティングについては [Embedded AI](Embedded-AI.md) を参照してください。

## コンポーネント詳細

セキュリティセンターまたはライセンスビューでコンポーネント（ライブラリ）をクリックすると、**コンポーネント詳細**パネルが開きます。

表示内容:

* 完全名、バージョン、エコシステム
* deps.dev のアップストリームプロジェクトレコードから取得した**プロジェクト説明**、ホームページ、ソースリポジトリへのリンク — OpenSSF Scorecard を取得する際にすでに呼び出している API をそのまま使うため、追加コストなしでエンリッチメント時に埋められます
* CVSS スコア・説明・修正バージョンを含む CVE 一覧 — 上部のライセンス／バージョンバッジとは視覚的に区切られた**セキュリティ課題（Security Issues）**見出しの下にグループ化されます
* ライセンス名とコンプライアンス状態
* AI 生成のライセンスリスク要約（AI が設定されている場合）
* パッチ適用可否（Patchable / Non-Patchable / Unknown）
* 最新の利用可能バージョンと非推奨通知（deps.dev から取得）
* 依存関係パス（コンポーネントがどのように取り込まれているか）

上流に公開された説明がないパッケージについては、何も表示しない代わりにその旨を明示し、ソースリポジトリへのリンクを案内します。
