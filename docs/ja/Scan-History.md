# スキャン履歴

スキャン履歴ページには、プロジェクトに送信されたすべてのスキャンが新しい順に一覧表示されます。

URL: `/projects/{id}/scan-history`

---

## 表示内容

| カラム | 説明 |
|---|---|
| **スキャン ID** | 内部の数値識別子 |
| **バージョン** | スキャン時点のプロジェクトバージョン文字列 |
| **状態** | PENDING / SCANNING / ANALYZING / COMPLETED / FAILED |
| **コンポーネント数** | 検出されたコンポーネントの総数 |
| **送信日時** | スキャン送信のタイムスタンプ |
| **送信者** | ユーザーのメールアドレス（認証済み CLI スキャンまたは Quick Import の場合） |

---

## スキャンの状態

| 状態 | 説明 |
|---|---|
| `PENDING` | スキャンを受信、処理待ちのキューに入っている |
| `SCANNING` | 依存関係マニフェストを解析中 |
| `ANALYZING` | CVE・ライセンスのエンリッチメント進行中（OSV / deps.dev） |
| `COMPLETED` | すべてのエンリッチメントが完了、セキュリティセンターが最新状態 |
| `FAILED` | エラーが発生 — スキャン行のエラーメッセージを確認 |

---

## スキャンの削除

スキャン行の**削除**アイコンをクリックすると、そのスキャンレコードとすべてのコンポーネントデータが完全に削除されます。

> ⚠️ この操作は元に戻せません。スキャンを削除すると、リスクトレンドのグラフからも除外されます。

---

## スキャンの再送信

OsWL は**同じバージョン**文字列でのスキャン再送信をサポートしています。サーバーは既存のスキャンレコードをリセットし、新しいペイロードを再処理します。以前のスキャンがエンリッチメント途中で失敗した場合や、バージョンを上げずに依存関係が変わった場合に便利です。

再スキャンする方法: CLI（`POST /api/scan`）で同じバージョンを送信します — OsWL はバージョンの一致を検出し、自動的にレコードをリセットします。
