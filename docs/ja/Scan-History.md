# スキャン履歴

スキャン履歴ページには、プロジェクトに送信されたすべてのスキャンが新しい順に一覧表示されます。

URL: `/projects/{id}/scan-history`

---

## 表示内容

| カラム | 説明 |
|---|---|
| **状態** | PENDING / SCANNING / ANALYZING / COMPLETED / FAILED |
| **バージョン** | スキャン時点のプロジェクトバージョン文字列。FAILED 行にはバージョンの下に要約されたエラーメッセージも表示 |
| **送信日時** | スキャン送信のタイムスタンプ (`yyyy-MM-dd HH:mm`) |
| **ソース** | バージョンの取得元 — **Git** (GitHub 連携) または **CLI** (CLI スキャンツール); 取り込み履歴がない場合は `-` |
| **コンポーネント数** | 検出されたコンポーネントの総数 |

ページヘッダーにはスキャンの合計件数も表示されます。

---

## スキャンの状態

| 状態 | 説明 |
|---|---|
| `PENDING` | スキャンを受信、処理待ちのキューに入っている |
| `SCANNING` | 依存関係マニフェストを解析中 |
| `ANALYZING` | CVE・ライセンスのエンリッチメント進行中（OSV / deps.dev） |
| `COMPLETED` | すべてのエンリッチメントが完了、セキュリティセンターが最新状態 |
| `FAILED` | エラーが発生 — スキャン行のエラーメッセージを確認 |

---

## オフラインモード: 定義基準日

サーバーがオフライン（air-gapped）モード（`oswl.airgapped.enabled=true`）で実行されている場合、ページ上部に次のバナーが表示されます。

> オフラインモード — {date} 時点の脆弱性定義で分析された結果です。

日付はインポートされたオフラインスナップショットソースの中で最も古い定義基準日であり、監査担当者が分析時点の脆弱性データがどの程度新しかったかを確認できるようにします。air-gapped モードではないか、スナップショットの出所がない場合はバナーは非表示になります。

---

## スキャンの削除

削除は上部バーのバージョンドロップダウンから行います。バージョン項目にマウスを合わせると表示される**削除**（ゴミ箱）アイコンをクリックし、確認します。この操作には `SCAN_HISTORY_DELETE` 権限（または `SYSTEM_ADMIN` ロール）が必要で、該当するスキャンレコードとすべてのコンポーネントデータを完全に削除します。削除は監査ログに記録されます。

> ⚠️ この操作は元に戻せません。スキャンを削除すると、リスクトレンドのグラフからも除外されます。

---

## スキャンの再送信

OsWL は**同じバージョン**文字列でのスキャン再送信をサポートしています。サーバーは既存のスキャンレコードをリセットし、新しいペイロードを再処理します。以前のスキャンがエンリッチメント途中で失敗した場合や、バージョンを上げずに依存関係が変わった場合に便利です。

再スキャンする方法: CLI（`POST /api/scan`）で同じバージョンを送信します — OsWL はバージョンの一致を検出し、自動的にレコードをリセットします。
